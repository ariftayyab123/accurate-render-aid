# Implementation Tracking Standard

To preserve token spending and maintain project context without needing to read the entire codebase repeatedly, we document each feature implementation in this directory.

## Instructions
1. Before implementing a new feature or making substantial changes to an existing component, create a new file in this directory named after the feature (e.g., `feature_name.md`).
2. Include the following sections in the document:
   - **Context**: The business logic and requirements.
   - **Implementation Plan**: Outline of what will be modified or added.
   - **Status/Updates**: A log of what has been implemented and what is left.
3. Keep the file updated as the implementation evolves.

This folder should be committed to version control.
